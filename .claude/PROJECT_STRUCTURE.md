## Что это

Пост-сессионный анализатор телеметрии Assetto Corsa (оригинал, не ACC).
Записывает круги через AC Shared Memory, строит теоретический идеальный
круг (лучший отрезок трассы, склеенный из всех валидных кругов сессии),
находит повороты, где теряется время, и выдаёт текстовые советы на
русском (точка торможения, скорость в апексе, момент открытия газа).

Ключевые решения по скоупу (зафиксированы пользователем явно, не моё
предположение):
- Только **Assetto Corsa оригинал**, не ACC — другая структура Shared Memory.
- Только **пост-сессионный отчёт**, без live-подсказок во время заезда.
- Базовая линия для «потери времени» — **теоретический идеальный круг**,
  не лучший круг и не внешняя эталонная телеметрия.
- Советы — **rule-based**, без LLM в ядре (LLM-слой поверх — сознательно
  отложен, не забыт).

                               # проверяет, что static-структура реально непустая (acVersion/track),
                               # т.к. mmap.mmap(-1, size, tagname) на Windows СОЗДАЁТ новую пустую

                               # тихий стрим нулей вместо понятной ошибки "AC не запущена"

                                    # + точки-апексы с номером поворота (где апекс лежит физически)
      telemetry_chart_widget.py    # скорость/газ-тормоз/дельта, свой круг vs лучший круг
      corner_table_widget.py       # таблица поворотов, сортировка по потере времени;

                                # НО только ловит исключения внутри main(), не в импортах наверху
                                # файла; см. launchers/ ниже, почему это было недостаточно

launchers/                     # НОВОЕ 2026-10-24: точки входа для PyInstaller, ВНЕ пакета motorai/
  calibrate.py                  # -> MotorAICalibrate.exe
  record.py                     # -> MotorAIRecord.exe
  viewer.py                     # -> MotorAI.exe (+ фолбэк на ctypes.windll.MessageBoxW,
                                 #    т.к. у windowed-сборки нет консоли вообще)
  report.py                     # -> MotorAIReport.exe
                                 # Все четыре: импорты motorai.* отложены ВНУТРЬ try/except
                                 # (а не на верхнем уровне файла) — иначе сбой импорта происходит
                                 # ДО того, как guard успевает подключиться, и окно закрывается
                                 # мгновенно без единой напечатанной строки. Это и была причина

tests/                         # pytest, все проходят на macOS (ядро кроссплатформенно) — 19/19 OK
  test_resample.py
  test_pipeline.py             # end-to-end на синтетических данных: resample->optimal->corners->tips;
                                # + локация апекса (в метрах, в пределах длины трассы), промах мимо
                                # апекса == 0 при сравнении эталонного круга с самим собой
  test_recorder.py             # границы круга / валидность, без реального mmap
  test_session_store.py        # сохранение/загрузка сессии на диск (включая track_length_m)

README.md                      # обзор + быстрый старт
requirements.txt
.gitignore                     # .venv, __pycache__, .pytest_cache, build/dist, *.spec, report.html, .DS_Store

## Как это всё связано (поток данных)

1. `capture.run_session` пишет сессию на диск через `storage.session_store`
   (один `.parquet` на круг + `meta.json` + `laps.json`).
2. `ui.app` / `report.__main__` загружают сессию через `SessionStore.load_session`
   и зовут `analysis.summary.analyse_session(...)`.
3. `analyse_session`: `resample_lap` каждого валидного круга → `build_optimal_lap`
   → `detect_corners` на самом быстром валидном круге → `build_corner_tips`
   сравнивает анализируемый круг с самым быстрым и с идеалом.
4. Результат (`SessionReport`) рендерится в `ui.main_window.MainWindow` или
   в `report.html_report.generate_html_report`.
5. `ui.app` больше не выбирает сессию сам — он строит через
   `ui.session_entries.build_entries(store, extra_session=args.session)`
   список всех записанных сессий (+ демо последним пунктом) и передаёт его
   целиком в `MainWindow`. Пользователь переключает сессии прямо в
   открытом окне через комбобокс «Сессия:» в хедере — перезапуск не нужен.

## Известные пробелы / риски (актуально на 2026-10-24)

Полный список обсуждался с пользователем в чате; ключевое:

1. **Раскладка `capture/structures.py` — кросс-проверена через веб-поиск
   (2026-10-24), но не протестирована на живой игре.** Сверил поле-в-поле
   с двумя независимыми open-source реализациями `sim_info.py` (проекты
   `prunn/ACTV` и `ev-agelos/ac_dashboard`) + документацией
   `dcratliff19/AC-SimInfo-Docs-Markdown`:
   - `SPageFilePhysics` — 60/60 полей совпадают точно (включая все, что
     реально читаю: `gas`, `brake`, `steerAngle`, `speedKmh`, `gear`,
     `rpms`, `numberOfTyresOut`).
   - `SPageFileGraphic` — 30/30 полей совпадают (включая `status`,
     `session`, `completedLaps`, `iCurrentTime`, `iLastTime`, `iBestTime`,
     `isInPit`, `normalizedCarPosition`, `carCoordinates`, `isInPitLane` —
     в одном источнике названо `isInPitLine`, это то же самое смещение,
     просто другое имя в другой версии обёртки).
   - `SPageFileStatic` — совпадают поля 1–16 и 20–42, включая
     `trackSPlineLength` (позиция подтверждена). Поля 17–19
     (`maxTurboBoost` + два float) расходятся только по имени —
     `deprecated1/deprecated2` у меня vs `airTemp/roadTemp` в чуть более
     старой версии обёртки — это один и тот же слот из 2×float, Kunos,
     судя по всему, депрекейтнул эти поля, не трогая офсеты. Последнее
     поле `isOnline` не подтверждено независимо, но я его не читаю.
   - Остаточный риск низкий и сосредоточен в полях, которые код не
     использует. **Но это всё ещё не замена реальному прогону** —
     `MotorAICalibrate.exe` на Windows с запущенной игрой нужен перед тем,
     как доверять записям.
2. Детекция поворотов (`analysis/corners.py`) — эвристика (перцентиль
   кривизны + сглаживание), откалибрована только на синтетической трассе.
   `np.gradient` не оборачивается по кругу → возможен артефакт на повороте,
   который физически лежит на стартовой прямой.
3. Валидность круга проверяется грубо: только съезд с трассы (>2 колёс) и
   заезд в питлейн. Контакт со стеной/трафик не отсекаются.
4. Нет управления местом на диске (старые сессии не чистятся).
5. `build.bat`/PyInstaller **прогонялся пользователем на реальной Windows**
   (2026-10-24) — результат: собранные .exe (проверено на MotorAICalibrate)
   мгновенно закрывались, окно появляется и тут же пропадает, без единого
   видимого сообщения. **Причина, которую нашёл и исправил**: все четыре
   PyInstaller-сборки указывали прямо на скрипты ВНУТРИ пакета
   (`motorai\capture\verify_capture.py` и т.п.), и `console_guard.py` ловил
   исключения только ВНУТРИ `main()` — если падает сам импорт
   `motorai.*` (на верхнем уровне файла, до вызова `run_with_pause`),
   guard вообще не успевает подключиться, и консоль Windows закрывает окно
   сразу, т.к. никто не вызвал `input()`. Эмулировал PyInstaller-сборку
   локально на macOS (та же логика анализа импортов, что и на Windows) —
   старый вариант на Mac собрался и запустился нормально, так что не 100%
   воспроизвёл именно Windows-сценарий, но сама архитектурная дыра в
   guard'е — реальна и исправлена независимо от точной причины.
   **Фикс**: точки входа вынесены в `launchers/*.py` (вне пакета
   `motorai/`), импорты `motorai.*` отложены внутрь `try/except` в каждом
   лончере — теперь ЛЮБОЙ сбой (включая сбой самого импорта, не только
   исключение внутри `main()`) печатается и держит окно открытым до Enter.
   Заодно нашёл и починил реальный смежный баг в `capture/reader.py`:
   `mmap.mmap(-1, size, tagname)` на Windows **создаёт новую пустую мапу**,
   если AC не запущена, а не кидает ошибку — `open()` раньше "успешно"
   открывался и `poll()` тихо стримил одни нули вместо понятной ошибки.
   **Ещё не подтверждено**: сработал ли этот фикс именно на машине
   пользователя — ждём пересборки и обратной связи. Если проблема
   повторится — нужен точный текст ошибки (теперь он должен появиться).
6. Нет code signing — Windows SmartScreen вероятно предупредит при первом запуске.
7. ~~В UI нет браузера сессий~~ — **сделано 2026-10-24**: комбобокс
   «Сессия:» в `MainWindow`, логика построения списка и выбора стартового
   индекса вынесена в `ui/session_entries.py` (чистый Python, тестируется
   без Qt). Попутно починена `track_length_m` — раньше для реальных
   (не demo) сессий она была жёстко `None` и советы показывали «м» как
   абстрактные единицы; теперь `static.trackSPlineLength` пишется в
   `meta.json` при записи (`capture/run_session.py`) и читается при
   загрузке — затронуло `storage/session_store.py` (`SessionMeta.track_length_m`)
   и `report/__main__.py` (тот же баг там тоже был).
8. У браузера сессий нет удаления/переименования — только просмотр списка.
   Нет индикации, если две сессии совпадают по треку+машине (только метка
   времени отличает).
9. ~~Нет явного указания, где находится апекс, и нет детекции промаха мимо
   апекса~~ — **сделано 2026-10-24**: `tips.py._apex_line_miss` считает
   боковое (перпендикулярное касательной) отклонение позиции машины от
   линии лучшего круга в точке апекса (`car_x`/`car_z`, метры — не зависит
   от `track_length_m`), с порогом `MIN_NOTABLE_APEX_MISS_M = 1.0` м и
   знаком направления («левее»/«правее»). `CornerTip.apex_position_m` даёт
   абсолютную дистанцию апекса от старта. На карте трассы (`track_map_widget`)
   апексы показаны точками с номером поворота. Ограничение: это отклонение
   от ЛИНИИ ЛУЧШЕГО КРУГА (самого быстрого валидного круга сессии), а не от
   геометрии трассы/поребрика — нет данных о реальных границах трассы,
   так что «промах» тут означает «отличие от твоего же лучшего заезда»,
   не «съехал с идеальной линии трассы».

> Примечание про тестирование на Windows: гонять это в Docker-образе
> Windows не вариант — Docker Desktop на macOS не поддерживает настоящие
> Windows-контейнеры (нужно ядро Windows-хоста), образы на базе QEMU
> (типа `dockur/windows`) без KVM на Mac либо не взлетят, либо будут
> эмулировать процессор программно (часы на установку одной Windows), а
> Assetto Corsa всё равно не запустится без проброса GPU. К тому же в
> этой среде нет инструмента управления GUI/VNC. Единственный практичный
> способ снизить этот риск без реальной Windows-машины — веб-поиск
> референсных реализаций (как сделано в п.1 выше); реальная проверка
> телеметрии всё равно требует настоящего Windows-ПК с купленной игрой.
