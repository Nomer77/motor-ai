# Настройка на Windows

## 1. Собрать .exe (один раз)

Нужен установленный Python 3.10+ ([python.org](https://www.python.org/downloads/),
при установке отметь "Add python.exe to PATH") — но это нужно только для
самой сборки. После неё Python больше не понадобится.

Скопируй папку проекта на Windows-ПК и дважды кликни **`build.bat`**
в корне проекта (или запусти его из консоли). Он сам:
- создаст виртуальное окружение,
- поставит зависимости,
- соберёт четыре `.exe` в папку `dist\`.

Первый запуск — несколько минут (скачивание зависимостей), дальше
пересборка быстрее.

> Почему нельзя было прислать готовый `.exe` сразу: PyInstaller не умеет
> кросс-компилировать — Windows-бинарник можно собрать только на Windows.
> Если захочешь, чтобы сборка происходила "в облаке" (GitHub Actions) без
> этого скрипта — дай знать, это тоже можно настроить отдельно.

Результат:

| Файл | Зачем |
|---|---|
| `dist\MotorAICalibrate\MotorAICalibrate.exe` | Разовая проверка, что телеметрия читается верно (шаг 2) |
| `dist\MotorAIRecord\MotorAIRecord.exe` | Запись заезда, пока ты едешь (шаг 3) |
| `dist\MotorAI\MotorAI.exe` | Просмотр отчёта (шаг 4) |
| `dist\MotorAIReport\MotorAIReport.exe` | Экспорт сессии в отдельный `.html` |

Сделай ярлыки на рабочий стол для `MotorAIRecord.exe` и `MotorAI.exe` —
это единственные два, которыми пользуешься постоянно.

Каждый `.exe` лежит в своей папке (сборка `--onedir`, а не один файл) —
так приложение стартует быстрее, папку просто не разбивай и не
переноси только `.exe` отдельно от соседних файлов.

## 2. Калибровка захвата телеметрии (сделать один раз)

Структуры памяти в `motorai/capture/structures.py` основаны на
общеизвестном (но не проверенном здесь, на macOS, при разработке)
описании AC Shared Memory. Перед тем как записывать настоящие сессии —
проверь, что всё читается правильно:

1. Запусти Assetto Corsa, выйди на трассу в любом режиме (Practice/Hotlap).
2. Запусти `MotorAICalibrate.exe`.
3. Сверь вывод с показаниями в игре: скорость, передача, обороты должны
   совпадать (с точностью до округления); `gas`/`brake` должны плавно
   меняться от 0 до 1 при нажатии педалей; `pos` должен расти от 0 до 1
   за круг и скачком возвращаться к ~0 на финишной прямой.
4. Если что-то выглядит как мусор (нереальная скорость, обороты —
   огромное число) — значит версия AC сдвинула раскладку структуры.
   Сравни `structures.py` с файлом `sim_info.py`, который Kunos кладёт в
   `Documents\Assetto Corsa\apps\python\**\sim_info.py` (ставится вместе
   с любым Python-приложением для AC) — там то же самое описание struct,
   актуальное для твоей версии игры. Скажи мне, что расходится — поправлю.

## 3. Запись сессии

Запусти `MotorAIRecord.exe`, едь столько кругов, сколько нужно, закрой
окно (или Ctrl+C) когда закончил. Круги сохраняются по мере прохождения —
закрытие окна ничего не теряет, кроме текущего незаконченного круга.
Сессия ложится в `Documents\MotorAI\sessions\<track>__<car>__<timestamp>\`.

## 4. Просмотр отчёта

Запусти `MotorAI.exe` — откроется последняя записанная сессия. Чтобы
открыть сессию и круг не из командной строки, передай аргументы через
ярлык (ПКМ → Свойства → "Объект" → дописать `--session "C:\путь"`) или
запускай из консоли:

```
MotorAI.exe --session "C:\...\MotorAI\sessions\..."
MotorAIReport.exe --session "C:\...\...\..." --out report.html
```

## Если что-то не собралось / не запустилось

`MotorAICalibrate.exe`, `MotorAIRecord.exe` и `MotorAIReport.exe` при
ошибке печатают её в консоль и ждут Enter, прежде чем закрыть окно — не
должно "мигнуть и пропасть". `MotorAI.exe` (оконное приложение, без
консоли) покажет всплывающее окно с текстом ошибки вместо тишины.

Если сборка в `build.bat` падает — пришли текст ошибки, которая
осталась на экране (`pause` в конце скрипта её не даст закрыть).
